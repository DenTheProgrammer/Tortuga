Tortuga / uTorrent: проверка скорости на Invite

1. Полностью закрой Tortuga и uTorrent, включая значки в трее.
2. Вручную отключи VPN. Пока идёт тест, останови другие загрузки и видео.
3. Открой Run-Benchmark.cmd двойным щелчком.

Тест автоматически найдёт единственный файл Invite / «Приглашение» с расширением
.torrent в папке Downloads. Если файлов несколько, укажи нужный:
  Run-Benchmark.cmd --torrent "C:\полный путь\Invite.torrent"

В комплекте есть обе проверенные программы. Node.js уже установлен на этом ПК;
другие зависимости и установка клиентов для теста не нужны.

Обычно выполняются четыре последовательные загрузки:
  проход 1: Tortuga, затем uTorrent;
  проход 2: uTorrent, затем Tortuga.
Они используют отдельные профили и отдельные пустые папки. Проверенные тестовые
копии фильма удаляются после замера. Чтобы сохранить их, добавь --keep-downloads.
Для двух загрузок вместо четырёх: Run-Benchmark.cmd --rounds 1
По умолчанию каждый клиент получает не более 30 минут; изменить: --timeout 900

Клиентам заданы неограниченные скорости, обычная загрузка без последовательного
режима, TCP/uTP и лимиты подключений 128. Фактические настройки сохраняются.
По умолчанию в каждый проход копируется одна и та же начальная копия DHT-кеша
соответствующего установленного клиента. Чтобы проверить холодный старт:
  Run-Benchmark.cmd --cold
При этом обычные профили программ и настройки VPN не меняются. Если VPN активен
при запуске или появился между проходами, тест остановится.

Результат находится в results\<время запуска>:
  report.html       — таблица и график; открывается обычным браузером;
  report.txt/json   — сводные результаты;
  logs-reports.zip  — архив логов и отчётов для последующего разбора;
  round-*           — CSV, сырые замеры, пиры, соединения и настройки каждого прохода.

Архив для разбора не содержит фильм, программы или профили с паролями API.
URL трекеров в отчётных логах очищаются от query-параметров. Адреса пиров и сетевые
параметры сохраняются, поскольку нужны для анализа маршрута и состава пиров.

Главная сравниваемая скорость — проверенный объём фильма / полное время загрузки,
включая ожидание пиров. Отдельно сохранены старт клиента, первый учтённый байт,
скорость после старта передачи, текущая и максимальная скорость по индикатору.
У клиентов могут различаться сглаживание индикатора и набор подключённых пиров.
uTorrent округляет прогресс до 0,1%, поэтому секундная скорость по прогрессу шумная.
CPU и память измеряются для главного процесса клиента; process_io — весь I/O
процесса, включая сокеты. Это не отдельный замер физического диска.
Даже порядок AB/BA не устраняет изменение раздачи и сети полностью. Разница в
одном замере ещё не доказывает преимущество движка. Сырые логи помогут проверить
пиры, протоколы, ожидание старта, пики и возможные ограничения ресурсов.

Проверка самого инструмента без скачивания фильма:
  Run-Benchmark.cmd --self-test --rounds 2
Она использует искусственную раздачу 8 МБ на localhost; можно выполнять с VPN.
Результаты этой проверки не являются сравнением скорости скачивания Invite.
